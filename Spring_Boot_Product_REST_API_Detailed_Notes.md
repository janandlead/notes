# Spring Boot REST API – Complete CRUD Notes

**Technology:** Java 21, Spring Boot 3, Spring Web, Spring Data JPA, Lombok, relational database  
**Example application:** Product Management REST API  
**Audience:** Beginners and Java/Spring Boot students  
**Scope:** GET, POST, PUT, DELETE; no Bean Validation

---

## 1. What is a REST API?

**REST** stands for **Representational State Transfer**. A REST API lets a client (browser, Postman, mobile application, Angular/React frontend, or another microservice) interact with server-side resources over HTTP.

In this project, the resource is a **Product**. Each product has an ID, name, category, availability, and price.

**Example request flow:**

```text
Postman / Frontend
       |
       | HTTP request (GET / POST / PUT / DELETE)
       v
ProductController (@RestController)
       |
       | Calls service method
       v
ProductService (@Service)
       |
       | Calls repository method
       v
ProductRepository (JpaRepository)
       |
       | SQL generated by Hibernate/JPA
       v
Database: products table
       |
       +----> Repository -> Service -> Controller -> JSON HTTP response
```

### HTTP methods at a glance

| Method | Purpose | Example URL | Typical success status | Request body? |
|---|---|---|---|---|
| GET | Read all products | `/api/products` | `200 OK` | No |
| GET | Read one product | `/api/products/1` | `200 OK` | No |
| POST | Create a product | `/api/products` | `201 Created` | Yes |
| PUT | Replace/update an existing product | `/api/products/1` | `200 OK` | Yes |
| DELETE | Remove a product | `/api/products/1` | `204 No Content` | No |

**Important:** The URLs above assume the application runs on `http://localhost:8080` and the controller uses `@RequestMapping("/api/products")`.

## 3. Entity: Product.java

```java
package com.durga.spring_rest_api.entity;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

@Entity
@Table(name = "products")
@Getter
@Setter
@NoArgsConstructor
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String category;

    @Column(name = "is_avialable")
    private Boolean available = false;

    private double price;
}
```

### Entity annotations explained

| Annotation | Package | Purpose |
|---|---|---|
| `@Entity` | `jakarta.persistence` | Marks the class as a JPA-managed database entity. |
| `@Table(name = "products")` | `jakarta.persistence` | Maps this entity to the `products` table. |
| `@Id` | `jakarta.persistence` | Declares the primary key. |
| `@GeneratedValue(strategy = GenerationType.IDENTITY)` | `jakarta.persistence` | Database generates the ID, typically using an identity/auto-increment column. |
| `@Column(name = "is_avialable")` | `jakarta.persistence` | Maps the Java `available` property to the existing database column `is_avialable`. |
| `@Getter` | `lombok` | Generates getter methods, such as `getName()`. |
| `@Setter` | `lombok` | Generates setter methods, such as `setPrice(double price)`. |
| `@NoArgsConstructor` | `lombok` | Generates a zero-argument constructor needed by JPA. |

**Note:** `is_avialable` is intentionally kept with the spelling from your existing database mapping. If you later rename the column, update the database and entity together. `Boolean` allows `true`, `false`, and `null`; its Java field initializer defaults newly constructed objects to `false` unless overwritten. `double` is kept to match your entity; for currency in production, `BigDecimal` is usually a better choice.

## 4. DTOs: Why use them?

**DTO** stands for **Data Transfer Object**. DTOs describe what clients send and receive without exposing the persistence entity directly.

- `ProductRequest`: Data received from a POST or PUT request. Does not include generated ID.
- `ProductResponse`: Data returned to the client. Includes generated ID.
- Java `record`: Concise immutable data carrier introduced before Java 21 and fully supported in Java 21. Record accessors use `name()` rather than `getName()`.

### ProductRequest.java

```java
package com.durga.spring_rest_api.dto;

public record ProductRequest(
        String name,
        String category,
        Boolean available,
        double price
) {}
```

### ProductResponse.java

```java
package com.durga.spring_rest_api.dto;

public record ProductResponse(
        Long id,
        String name,
        String category,
        Boolean available,
        double price
) {}
```

**Why no `@RequestBody` on a DTO class?** `@RequestBody` belongs on a controller method parameter; it tells Spring to deserialize the HTTP request body into that parameter.

## 5. Repository: ProductRepository.java

```java
package com.durga.spring_rest_api.repository;

import org.springframework.data.jpa.repository.JpaRepository;
import com.durga.spring_rest_api.entity.Product;

public interface ProductRepository extends JpaRepository<Product, Long> {
}
```

`JpaRepository<Product, Long>` means:

- `Product`: entity type.
- `Long`: primary-key type.
- Spring Data JPA provides the repository implementation automatically.
- `@Repository` is **optional** on this interface when it is discovered as a Spring Data repository; it is not required for the example to work.

### Important built-in repository methods

| Method | Meaning | Used for |
|---|---|---|
| `save(product)` | Inserts a new entity or saves changes to an existing entity, depending on entity state. | POST, PUT |
| `findAll()` | Retrieves all rows (not paginated). | GET all |
| `findById(id)` | Returns `Optional<Product>`; may be empty. | GET by ID, PUT |
| `existsById(id)` | Checks whether an ID exists. | DELETE check |
| `deleteById(id)` | Deletes by ID. | DELETE |
| `delete(product)` | Deletes a supplied entity. | Alternative DELETE |
| `count()` | Counts rows. | Reporting |

**For large tables:** Prefer `findAll(Pageable)` instead of loading every record at once.

## 6. Service: ProductService.java (complete code)

```java
package com.durga.spring_rest_api.service;

import java.util.List;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.web.server.ResponseStatusException;

import com.durga.spring_rest_api.dto.ProductRequest;
import com.durga.spring_rest_api.dto.ProductResponse;
import com.durga.spring_rest_api.entity.Product;
import com.durga.spring_rest_api.repository.ProductRepository;

import lombok.RequiredArgsConstructor;

@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductRepository productRepository;

    // GET: all products
    public List<ProductResponse> getAllProducts() {
        return productRepository.findAll()
                .stream()
                .map(this::mapToResponse)
                .toList();
    }

    // GET: product by ID
    public ProductResponse getProductById(Long id) {
        Product product = productRepository.findById(id)
                .orElseThrow(() -> new ResponseStatusException(
                        HttpStatus.NOT_FOUND, "Product not found"));
        return mapToResponse(product);
    }

    // POST: create product
    public ProductResponse createProduct(ProductRequest request) {
        Product product = new Product();
        product.setName(request.name());
        product.setCategory(request.category());
        product.setAvailable(request.available());
        product.setPrice(request.price());

        Product savedProduct = productRepository.save(product);
        return mapToResponse(savedProduct);
    }

    // PUT: update existing product
    public ProductResponse updateProduct(Long id, ProductRequest request) {
        Product product = productRepository.findById(id)
                .orElseThrow(() -> new ResponseStatusException(
                        HttpStatus.NOT_FOUND, "Product not found"));

        product.setName(request.name());
        product.setCategory(request.category());
        product.setAvailable(request.available());
        product.setPrice(request.price());

        Product updatedProduct = productRepository.save(product);
        return mapToResponse(updatedProduct);
    }

    // DELETE: remove product
    public void deleteProduct(Long id) {
        Product product = productRepository.findById(id)
                .orElseThrow(() -> new ResponseStatusException(
                        HttpStatus.NOT_FOUND, "Product not found"));
        productRepository.delete(product);
    }

    // Common mapper: Entity -> Response DTO
    private ProductResponse mapToResponse(Product product) {
        return new ProductResponse(
                product.getId(),
                product.getName(),
                product.getCategory(),
                product.getAvailable(),
                product.getPrice()
        );
    }
}
```

### Service annotations and keywords

- **`@Service`**: Marks the class as a Spring-managed service bean. It is a specialization of `@Component`.
- **`@RequiredArgsConstructor`**: Lombok generates a constructor for required fields, including `final` fields. Spring uses it to inject `ProductRepository`; with one constructor, `@Autowired` is not necessary.
- **`private final ProductRepository productRepository`**: Constructor-injected dependency that cannot be reassigned after construction.
- **`ResponseStatusException(HttpStatus.NOT_FOUND, ...)`**: A simple way to return HTTP 404 when the requested product does not exist. It is not Bean Validation.

### Java methods and operations used

- `new Product()`: Creates a new Java object; no database row exists yet.
- `request.name()`, `request.price()`: Read values from a Java record.
- `product.setName(...)`: Copies request data to an entity.
- `productRepository.save(product)`: Persists the new or changed entity.
- `findById(id)`: Looks up an entity by its primary key.
- `orElseThrow(...)`: Extracts the `Optional` value or throws an exception when empty.
- `findAll()`: Fetches all products.
- `.stream()`: Creates a Java Stream from a collection.
- `.map(this::mapToResponse)`: Transforms each `Product` into `ProductResponse` using a method reference.
- `.toList()`: Collects mapped stream elements into a list (unmodifiable list in modern Java).
- `delete(product)`: Removes the specified entity.
- `void`: The service delete method returns no value.
- `private`: The mapper is an implementation detail, not part of the service's public API.

### Why use a mapper?

The database returns a `Product` entity, but the HTTP client receives a `ProductResponse`. Keeping conversion in one method avoids repeated code and lets you change API fields independently of database mapping.

## 7. Controller: ProductController.java (complete code)

```java
package com.durga.spring_rest_api.controller;

import java.util.List;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import com.durga.spring_rest_api.dto.ProductRequest;
import com.durga.spring_rest_api.dto.ProductResponse;
import com.durga.spring_rest_api.service.ProductService;

import lombok.RequiredArgsConstructor;

@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor
public class ProductController {

    private final ProductService productService;

    @GetMapping
    public ResponseEntity<List<ProductResponse>> getProducts() {
        return ResponseEntity.ok(productService.getAllProducts());
    }

    @GetMapping("/{id}")
    public ResponseEntity<ProductResponse> getProductById(@PathVariable Long id) {
        return ResponseEntity.ok(productService.getProductById(id));
    }

    @PostMapping
    public ResponseEntity<ProductResponse> createProduct(
            @RequestBody ProductRequest request) {
        ProductResponse response = productService.createProduct(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(response);
    }

    @PutMapping("/{id}")
    public ResponseEntity<ProductResponse> updateProduct(
            @PathVariable Long id,
            @RequestBody ProductRequest request) {
        return ResponseEntity.ok(productService.updateProduct(id, request));
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteProduct(@PathVariable Long id) {
        productService.deleteProduct(id);
        return ResponseEntity.noContent().build();
    }
}
```

## 8. Controller annotations explained in detail

### `@RestController`

- Applied at class level.
- Combines `@Controller` and `@ResponseBody` semantics.
- Returns response data (typically JSON) rather than a view/template.
- Spring uses an HTTP message converter (commonly Jackson) to serialize DTOs to JSON.

### `@RequestMapping("/api/products")`

- Sets a common base URL for controller methods.
- Can also specify method, headers, `consumes`, and `produces` conditions.
- Here all endpoints begin with `/api/products`.

### `@GetMapping`

- Maps HTTP GET requests.
- Equivalent in intent to `@RequestMapping(method = RequestMethod.GET)`.
- `@GetMapping` handles `/api/products`.
- `@GetMapping("/{id}")` handles `/api/products/1`.

### `@PostMapping`

- Maps HTTP POST requests.
- Used to submit data and create a new product in this example.
- Works with `@RequestBody` to receive JSON.

### `@PutMapping("/{id}")`

- Maps HTTP PUT requests.
- The `{id}` segment identifies the existing resource to update.
- In this project, PUT updates **all editable fields**; the client should send a complete representation.

### `@DeleteMapping("/{id}")`

- Maps HTTP DELETE requests.
- Deletes the resource identified by `{id}`.

### `@PathVariable`

- Reads a value from the URL path.
- Example: `/api/products/7` maps `7` to the `Long id` argument.
- You can write `@PathVariable("id") Long productId` if the Java parameter name differs.

### `@RequestBody`

- Converts a JSON request body into the Java method parameter using an HTTP message converter.
- Example: `{"name":"Laptop"}` can be deserialized into `ProductRequest`.
- Missing/invalid JSON may still produce framework-level HTTP errors even without Bean Validation.

### `@RequiredArgsConstructor`

- Generates a constructor for `final` dependencies, enabling constructor injection without manually writing the constructor.

### `@ResponseBody` (concept)

- Writes the return value into the HTTP response body.
- Usually unnecessary to write explicitly when the class already uses `@RestController`.

### `@RequestParam` (related, not required here)

- Reads query parameters such as `/api/products?category=Electronics`.
- Example: `@RequestParam String category`.
- Useful later for filtering, searching, pagination, and sorting.

## 9. GET API: Read products

### When should you use GET?

Use GET to **retrieve** data without intentionally changing server state. Common examples: display product catalog, show product details, load dropdown options, or show inventory status.

**GET all:**

```http
GET http://localhost:8080/api/products
```

**Controller:**

```java
@GetMapping
public ResponseEntity<List<ProductResponse>> getProducts() {
    return ResponseEntity.ok(productService.getAllProducts());
}
```

**Service:**

```java
public List<ProductResponse> getAllProducts() {
    return productRepository.findAll().stream()
            .map(this::mapToResponse)
            .toList();
}
```

**Example response (`200 OK`):**

```json
[
  {"id":1,"name":"Laptop","category":"Electronics","available":true,"price":55000.0},
  {"id":2,"name":"Mouse","category":"Accessories","available":false,"price":800.0}
]
```

When the table is empty, this endpoint returns `200 OK` with `[]`.

**GET by ID:**

```http
GET http://localhost:8080/api/products/1
```

```java
@GetMapping("/{id}")
public ResponseEntity<ProductResponse> getProductById(@PathVariable Long id) {
    return ResponseEntity.ok(productService.getProductById(id));
}
```

If ID `1` does not exist, the service throws `ResponseStatusException` with `404 Not Found`.

**Properties of GET:**

- **Safe:** Intended for reading, not modifying state.
- **Idempotent:** Repeating the same GET has the same intended effect on server state (though returned data can change when other requests modify it).
- **Cacheable:** Can be cached when appropriate HTTP caching headers are supplied.

## 10. POST API: Create a product

### When should you use POST?

Use POST when a client wants the server to **create a new product** and let the database assign its ID. Examples: admin adds a new catalog item, inventory staff registers a new product.

**Request:**

```http
POST http://localhost:8080/api/products
Content-Type: application/json
```

```json
{
  "name": "Laptop",
  "category": "Electronics",
  "available": true,
  "price": 55000.0
}
```

**Controller:**

```java
@PostMapping
public ResponseEntity<ProductResponse> createProduct(@RequestBody ProductRequest request) {
    ProductResponse response = productService.createProduct(request);
    return ResponseEntity.status(HttpStatus.CREATED).body(response);
}
```

**Service execution, step by step:**

1. Spring converts JSON into a `ProductRequest` record.
2. `new Product()` creates an entity object.
3. `setName`, `setCategory`, `setAvailable`, `setPrice` copy fields.
4. `productRepository.save(product)` persists it.
5. The database generates the ID because of `GenerationType.IDENTITY`.
6. `mapToResponse(savedProduct)` creates the DTO.
7. Controller sends `201 Created` with JSON.

**Example response (`201 Created`):**

```json
{
  "id": 1,
  "name": "Laptop",
  "category": "Electronics",
  "available": true,
  "price": 55000.0
}
```

**Why `201` instead of `200`?** `201 Created` explicitly communicates that a new resource was created. A production API may also include a `Location` header pointing to `/api/products/1`; the simplified controller does not add it.

**Is POST idempotent?** Not generally. Repeating the same create request can insert multiple rows with different IDs.

## 11. PUT API: Update a product

### When should you use PUT?

Use PUT when a client wants to **replace the editable representation of an existing resource** at a known URL. Example: update a laptop's name, category, availability, and price.

**Request:**

```http
PUT http://localhost:8080/api/products/1
Content-Type: application/json
```

```json
{
  "name": "Dell Laptop",
  "category": "Computers",
  "available": false,
  "price": 60000.0
}
```

**Controller:**

```java
@PutMapping("/{id}")
public ResponseEntity<ProductResponse> updateProduct(
        @PathVariable Long id,
        @RequestBody ProductRequest request) {
    return ResponseEntity.ok(productService.updateProduct(id, request));
}
```

**Service execution, step by step:**

1. `@PathVariable` extracts product ID from the URL.
2. `@RequestBody` reads the updated product details.
3. `findById(id)` searches the existing product.
4. `orElseThrow(...)` returns `404` if it is missing.
5. Setters overwrite all editable fields on the existing entity.
6. `save(product)` persists the updated state.
7. DTO mapper builds the response; controller returns `200 OK`.

**Example response (`200 OK`):**

```json
{
  "id": 1,
  "name": "Dell Laptop",
  "category": "Computers",
  "available": false,
  "price": 60000.0
}
```

**Does PUT create the product if the ID does not exist?** Not in this implementation. It returns `404 Not Found` instead. Some other APIs choose to support create-or-replace semantics, but that is a separate design decision.

**Is PUT idempotent?** Yes, by intended HTTP semantics. Sending the same full update repeatedly should leave the resource in the same final state.

**PUT vs PATCH:** PUT generally represents a full replacement of editable state. PATCH is designed for partial modifications. Here, omitting a field from PUT can cause its Java default (`null` or `0.0`) to overwrite the previous value, so send every editable field.

## 12. DELETE API: Remove a product

### When should you use DELETE?

Use DELETE when a product must be removed, for example when an admin permanently removes a discontinued catalog entry. Whether to hard-delete or soft-delete is a business decision; this example performs a **hard delete**.

**Request:**

```http
DELETE http://localhost:8080/api/products/1
```

**Controller:**

```java
@DeleteMapping("/{id}")
public ResponseEntity<Void> deleteProduct(@PathVariable Long id) {
    productService.deleteProduct(id);
    return ResponseEntity.noContent().build();
}
```

**Service:**

```java
public void deleteProduct(Long id) {
    Product product = productRepository.findById(id)
            .orElseThrow(() -> new ResponseStatusException(
                    HttpStatus.NOT_FOUND, "Product not found"));
    productRepository.delete(product);
}
```

**Step-by-step:**

1. Read ID from the URL.
2. Find the existing product.
3. Return `404` if the product does not exist.
4. Call `delete(product)` to remove the entity.
5. Return `204 No Content` with **no response body**.

**Is DELETE idempotent?** Yes in terms of intended final resource state. After one successful delete, the resource is absent; repeated calls do not make it more absent. This implementation returns `404` for a repeated delete because the resource is already missing. Different response codes do not violate idempotency.

## 13. `ResponseEntity` explained

`ResponseEntity<T>` represents an HTTP response with a **status code**, optional **headers**, and optional **body**.

| Expression | Result | Typical use |
|---|---|---|
| `ResponseEntity.ok(data)` | `200 OK` + JSON body | GET, PUT |
| `ResponseEntity.status(HttpStatus.CREATED).body(data)` | `201 Created` + body | POST |
| `ResponseEntity.noContent().build()` | `204 No Content`, no body | DELETE |
| `ResponseEntity.notFound().build()` | `404 Not Found`, no body | Missing resource (alternative) |
| `ResponseEntity.badRequest().build()` | `400 Bad Request`, no body | Bad request (alternative) |

### What do the generic types mean?

- `ResponseEntity<ProductResponse>`: response body contains one DTO.
- `ResponseEntity<List<ProductResponse>>`: response body contains a list of DTOs.
- `ResponseEntity<Void>`: response has no body.

### `status()`, `body()`, and `build()`

- `status(HttpStatus.CREATED)`: sets the status for the response builder.
- `.body(response)`: finishes building the response with a body.
- `.noContent()`: starts a builder with HTTP 204.
- `.build()`: finishes building a response without a body.

## 14. HTTP status codes to remember

| Code | Meaning | Example |
|---|---|---|
| `200 OK` | Request succeeded with a response | GET, PUT |
| `201 Created` | New resource created | POST |
| `204 No Content` | Request succeeded without response body | DELETE |
| `400 Bad Request` | Invalid HTTP request, malformed JSON, or incompatible input | Bad JSON |
| `404 Not Found` | Requested resource does not exist | GET/PUT/DELETE unknown ID |
| `405 Method Not Allowed` | HTTP method is not supported at that route | PATCH when no PATCH mapping exists |
| `415 Unsupported Media Type` | Request content type is not supported | Unsupported content type |
| `500 Internal Server Error` | Unhandled server-side failure | Unexpected application/database failure |

**Without Bean Validation:** No `@Valid`, `@NotBlank`, or `@NotNull` is used. However, Spring can still reject malformed JSON or incompatible types before calling your controller method. No custom global exception handler is required for the simple `ResponseStatusException` approach.

## 15. Annotation reference sheet

| Annotation | Applied to | Role |
|---|---|---|
| `@RestController` | Controller class | Exposes REST endpoints and serializes responses |
| `@RequestMapping` | Controller class or method | Defines common or specific request mapping |
| `@GetMapping` | Controller method | Handles GET |
| `@PostMapping` | Controller method | Handles POST |
| `@PutMapping` | Controller method | Handles PUT |
| `@DeleteMapping` | Controller method | Handles DELETE |
| `@RequestBody` | Controller parameter | Reads JSON body into Java object |
| `@PathVariable` | Controller parameter | Reads `{id}` from path |
| `@RequestParam` | Controller parameter | Reads query-string values |
| `@Service` | Service class | Registers service-layer Spring bean |
| `@RequiredArgsConstructor` | Class | Generates constructor for required fields |
| `@Entity` | Entity class | Enables JPA entity mapping |
| `@Table` | Entity class | Specifies database table |
| `@Id` | Entity field | Specifies primary key |
| `@GeneratedValue` | Entity field | Configures ID generation |
| `@Column` | Entity field | Configures column mapping |
| `@Getter` / `@Setter` | Class or field | Lombok accessor generation |
| `@NoArgsConstructor` | Class | Lombok zero-argument constructor |
| `@Transactional` | Service class or method (optional here) | Defines transaction boundary |

### Optional: `@Transactional`

Spring Data JPA repository write methods are transactional by default. For more complex business operations involving multiple repository calls, place `@Transactional` on the service method to make them part of a single transaction. `@Transactional(readOnly = true)` is a useful hint for read-only service operations. It is **not required** to understand or run the simple examples above.

## 18. Common mistakes and troubleshooting

**1. `404 Not Found` on every endpoint:** Check the class-level URL (`/api/products`), application port, package scanning, and whether the application started.

**2. `405 Method Not Allowed`:** You may be sending GET to a POST-only route or using the wrong HTTP verb.

**3. `415 Unsupported Media Type`:** Set `Content-Type: application/json` for JSON POST and PUT requests.

**4. `400 Bad Request`:** Check JSON syntax and field types; for example, `price` must be a number.

**5. `500` database errors:** Verify database connection, schema, and the exact column name `is_avialable`.

**6. Product fields not updating:** Check setters, request JSON property names, and whether `save()` is called.

**7. `@RequiredArgsConstructor` seems not to work:** Check Lombok dependency and IDE annotation-processing support.

**8. Why doesn't the client send `id` in POST?** The database generates it using `GenerationType.IDENTITY`.

**9. What happens if `available` is omitted from JSON?** The `Boolean` in `ProductRequest` can be `null`, and this service copies it to the entity, replacing the entity's initial `false`. There is no validation in this example.

**10. Why might PUT overwrite missing values?** Java record fields that are absent from JSON can deserialize to `null` for references and `0.0` for primitive `double`; this example performs a full update, not a partial update.

## 19. Frequently asked interview questions

**Q1. Difference between `@Controller` and `@RestController`?**  
`@Controller` commonly serves MVC views; `@RestController` includes `@ResponseBody` behavior and is convenient for JSON APIs.

**Q2. Difference between `@RequestBody` and `@PathVariable`?**  
`@RequestBody` reads request payload; `@PathVariable` reads a value embedded in the URL path.

**Q3. Why use `ResponseEntity`?**  
It allows explicit control of HTTP status, headers, and response body.

**Q4. What is the difference between POST and PUT?**  
POST is commonly used to create under a collection URL; PUT replaces the state of a resource identified by its URL.

**Q5. Why return `204` for DELETE?**  
Deletion succeeded and the server has no representation to return.

**Q6. Why use DTOs instead of returning entities?**  
To control the API contract and avoid exposing persistence implementation details.

**Q7. What does `Optional<Product>` mean?**  
The lookup may return a Product or no value; `orElseThrow()` handles the missing case.

**Q8. What is `JpaRepository`?**  
A Spring Data interface that provides common persistence methods without manually writing SQL for each CRUD operation.

**Q9. Why is constructor injection recommended?**  
Dependencies are explicit, can be final, and are easier to test.

**Q10. Are GET, PUT, and DELETE idempotent?**  
Yes, by HTTP semantics; POST is not guaranteed to be idempotent.

**Q11. Is `@Transactional` mandatory on each controller?**  
No. Transaction boundaries typically belong in the service layer when needed, and repository methods already have transaction behavior.

**Q12. Is `@Valid` required for REST APIs?**  
No. Bean Validation is optional; this lesson intentionally omits it.

## 21. Quick revision summary

```text
GET    /api/products       -> getAllProducts()   -> findAll()       -> 200
GET    /api/products/{id}  -> getProductById()    -> findById()      -> 200 / 404
POST   /api/products       -> createProduct()     -> save()          -> 201
PUT    /api/products/{id}  -> updateProduct()     -> findById()+save() -> 200 / 404
DELETE /api/products/{id}  -> deleteProduct()     -> findById()+delete() -> 204 / 404
```

**Core takeaway:** The **controller** handles HTTP, the **service** handles business logic and DTO mapping, the **repository** handles persistence, and the **entity** maps to the database. Use the correct HTTP method and status code to communicate what happened.
